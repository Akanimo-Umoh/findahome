# Admin Listings: Backend Follow-ups

## Still Blocking

4. Admin listing access and public filtering. `GET /api/property` currently returns pending and rejected properties publicly. Please filter public listing results to `approved` only and provide a protected admin endpoint that returns every status for moderation. The admin frontend needs `{ success, properties }`.

5. Public listing detail. The property detail route is public, but its controller assumes `req.user` exists. Please make it safe for anonymous visitors and avoid creating view notifications for admins and the property's owner; notify only other viewers.

## Already Available And Connected

- Property status changes use `PUT /api/property/status/:id` and accept `{ status, reason? }`; approval/rejection notifications and optional rejection reason are supported.
- Flagging uses `PATCH /api/property/:id/flag` with `{ flagged, reason? }`.
- Admin notes use `POST /api/property/:propertyId/notes` with `{ note }` and notify the agent.
- Property status history and readable property codes are generated by the model.
- The backend accepts `ownerId` on admin property creation. The add-property admin button remains out pending the product decision requested in item 14.
- Persisting the moderation checklist remains optional (item 13) and is not required for the current page integration.
